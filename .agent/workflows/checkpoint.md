# Checkpoint workflow

Update `.agent/STATE.md` when a meaningful unit of work completes, an investigation concludes, an architectural decision is made, validation changes, a blocker or strategy change appears, before likely context compaction, before handoff, or before ending an incomplete session.

The checkpoint must state:

- objective and current phase;
- completed work and files/components involved;
- verified facts and important failed approaches;
- validation already run and its result;
- blockers and one concrete next action;
- the path of the active plan, decision, or investigation.

Keep it current and concise. Move detailed evidence to the referenced record. Do not record every command or turn the state file into a conversation log.
