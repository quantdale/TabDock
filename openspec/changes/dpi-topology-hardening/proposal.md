# DPI and topology hardening

## Why

TabDock now has closed presentation-integrity and visual-evidence qualification,
but the final v1.1 candidate remains qualification-only partly because the
physical topology matrix is still narrow. The proven host used a right-hand
secondary monitor at 96 DPI and a primary at 120 DPI. It did not physically
exercise negative virtual coordinates, a monitor above the origin,
150%/175%/200% scale, deeper mixed-DPI transitions, or the corresponding visual
evidence and title-centering behavior.

The predecessor visual campaign explicitly migrated four obligations here:
visual scope/topology acceptance (4.8), physical title-centering evidence
(18.6), dual-monitor transfer (19.2), and mixed-DPI before/after visual evidence
(19.3).

## What Changes

- Expand the deterministic topology laboratory with left-negative, above-origin,
  staggered, asymmetric-work-area, odd-size, 150%/175%/200% DPI, and mixed-DPI
  transition matrices.
- Add physical capability/preflight evidence for virtual screen, monitor/work
  rectangles, primary identity, effective DPI, relative placement, and exact
  candidate/run identity.
- Add supervised physical cells for bidirectional transfer, maximize/restore,
  title-centering, controlled topmost, split/single containment, and restricted
  mixed-DPI visual checkpoints.
- Make display layout/scale operator-controlled, snapshotted, verified, and
  restored; never manufacture a topology with registry hacks or blind UI input.
- Keep synthetic topology permanently ineligible for physical qualification.
- Keep production code out of scope unless a valid retained `FAIL_PRODUCT` or
  deterministic policy defect proves a concrete Shepherd invariant violation.
- Close the four migrated predecessor rows here.
- Keep broader real-app hardening separate.

## Non-Goals

- No reparenting, permanent topmost, global z-order fight, polling loop, or
  style stripping.
- No registry-based scaling hacks, unsupported display mutation, destructive
  automated hot-unplug, or unrestricted desktop capture.
- No claim that synthetic topology satisfies a physical mixed-DPI gate.
- No real-app campaign implementation.
- No retagging of the closed v1.1 binary or packets.

## Acceptance Boundary

Complete only when deterministic matrices pass as synthetic coverage, every
available physical cell has an exact-candidate supervised disposition, the
four migrated rows have row-level closure, any real product failure is
preserved/repaired/requalified minimally, environment restoration is proven,
and final build/test/OpenSpec/CI-safe gates pass. Real-app hardening remains the
next independent campaign.
